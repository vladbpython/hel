## [2.2.0]

### Added

**`Receiver` is now public: `hel::channel::Receiver`.** The receivers you get
  from `ShardReceiver::into_receivers()` already crossed the public API 
  (you pass a `Vec<Receiver<T, CAP>>` to the pool), but the type had no public name, 
  so you could not write your own functions over it.
  It is now public, so you can name
  it in your own functions and hand each receiver to its own worker:

  ```rust
  use hel::channel::Receiver;

  // sync: one thread per receiver
  fn worker(rx: Receiver<Event, CAP>) {
      while let Ok(event) = rx.recv() {
          // handle event
      }
  }

  for rx in shard_rx.into_receivers() {
      std::thread::spawn(move || worker(rx));
  }

  // async: one task per receiver
  async fn worker_async(rx: Receiver<Event, CAP>) {
      while let Ok(event) = rx.recv_async().await {
          // handle event
      }
  }

  for rx in shard_rx.into_receivers() {
      tokio::spawn(worker_async(rx));
  }
  ```

  Write the type as `Receiver<T, CAP>`. The third parameter (the channel backing)
  defaults to the internal `SeqInner`, so you never name it. Only the `Receiver`
  type is exposed: the `internal_channel` module, the `InnerChannel` trait, and
  the concrete backings stay private.

### Compatibility

Existing code keeps working unchanged.

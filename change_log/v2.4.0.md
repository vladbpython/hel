## [2.4.0]

### Deprecated

- **Macros `mpmc!` and `spsc!` are marked obsolete**, removal in the following
  major release. There is absolutely no benefit. If you need macros, create and write about it in git issue

### Fixed

- **Pool: task cancellation lost the tail of the pack.** The worker takes up to
  `batch_size` elements in one go, and the guard covered only the element
  that was in the handler. If runtime canceled the worker's task in the middle
  packs (application stop, `shutdown_timeout`), other elements
  were destroyed silently since they had already been taken out of the channel, so they did not fall into any
  processed, not in `dead_letter` (measurement: from a pack of 8 elements was returned
  1, seven were lost).

- **Pool: a broken config would hang the pool forever or drop the monitor.** Block on
  making a `Config` literal does not prevent assignments to its public fields, and
  `cfg.min_consumers = 10` with `max_consumers = 4` broke the pool twice, part
  shards were assigned to workers who are never created (their queues are nobody
  did not parse), and the scaling flow crashed during the `clamp` check and silently
  was dying.

- **`queued()` could show more channel capacity.** Blocking send
  reserves its position before waiting for free space, so
  blocked senders inflated the difference in counters above `CAP` (measured:
  6 with capacity 4). Domestic consumers defended themselves, and public
  `queued()` returned an inflated number. Now the answer is limited by capacity: channel
  physically cannot hold more `CAP` elements.

- **Panic in `key_fn` destroyed the entire packet.** Key function, custom
  code, and it was called directly while removing elements from the buffer: panic on
  one “crooked” element dropped the recess iterator and took the entire package with it
  (measured: 4 out of 4 are lost), and in all batch methods `shard_key` and
 `shard_group` including async. Now each key call is wrapped in
  interceptor and in case of panic the entire packet is collected back into the buffer (first
  grouped, then the untouched tail, the order inside the key is preserved) and
  only then does the panic continue.

- **`drain_batch(0, ..)` was spinning forever.** Reception with a zero limit does not return
  no elements, no sign of closure, so the drain cycle did not complete
  never. All four flush helpers (sync/async, element-wise/batch) are now
  raise the limit to 1.

- **`mpmc!` /`spsc!` macros no longer pass capacity 1 into the constructor.**
  The ring needs a capacity of at least 2, and rounding to the power of two does not
  changes (`1` is already a power of two), so `mpmc!(u64, 1)` used to go to
  the designer as is and fell there. Now the unit is rounded up to 2 in
  in the same way that 500 is rounded to 512.

- **Future channel implementations will not be able to bypass thread safety.**
  internal futures sending/receiving manual `unsafe impl Send` received
  mandatory requirement `Send + Sync` for the channel, it is now fulfilled
  always, but if internal traits ever become public,
  an unsafe implementation simply won't work.

### Modified

- **Two rounding helpers instead of one, as intended.**
  `nearest_power_of_two` now rounds **capacity**.
  The new `shard_power_of_two` rounds up the **number of shards**.

- **The `futures` dependency has been replaced with `futures-core` + `futures-util`.** From
  the entire façade used only the `Stream` trait and one combinator;
  now channel/executor/io/sink and macros do not stretch -the assembly tree
  users are noticeably easier. The public API hasn't changed: it's the same
  the `Stream` trait that `futures` re-exports.

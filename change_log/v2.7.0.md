## [2.7.0]

### Added

- Pool observability. The receivers live inside the pool, so queue depth was unreadable exactly where it matters most. Now the pool handle itself answers:
- `depths()` gives the queue depth of every shard, `shard_queued(i)` of one shard. The values come from a mirror the workers refresh after every dequeued batch and the monitor once per `sample_interval` (seeded at construction), so a reading is at most one tick stale. Both return `None` once the channels are gone. While any receiver is alive the values stay live, including after `stop()` while the workers drain their final batches; a shard whose worker is stuck inside a handler keeps its last published value. The handle holds no reference to the receivers at all, so it can neither keep a stopped pool's channels alive nor run item destructors inside a metrics call.
- `stats()` gives one read only snapshot of the whole pool: per worker busy, stalled, heartbeat of completed items and the shard whose batch it holds, per shard depth, current owner and placement target, plus all counters. The worker list covers every worker that ever existed and every observed shard owner and placement target (at least `max_active` rows): a retired worker can still own a shard, and a stalled one is exactly the row an incident needs. The row count follows the peak, so a pool that once scaled to its ceiling keeps the full list.
- `channels_closed` in the snapshot: true once every receiver is dropped. This also catches an async runtime tearing the worker tasks down without the pool ever being stopped, a state `stopped` alone cannot report; the queue depths are frozen history from that point.
- `takeovers()` counts shards moved off a stalled owner by `stall_takeover`.
- `shards()` on the pool handle.
- New public types `stats::Pool`, `stats::Worker`, `stats::Shard`.
- The snapshot is racy by design: good for dashboards and incident debugging, not for synchronization.
- Warning documented: do not clone a `Receiver` out of the pool to poll depth, the clone keeps the channel from ever closing. Use the pool methods instead.

### Fixed

- `ShardGroup::from_map` routed out-of-range group indexes into phantom shards. The index was normalized against the shard count rounded up to a power of two instead of `num_groups`, so a key could land on a shard no caller-visible group maps to: the ring filled and every later send bounced with Full forever. Indexes now fold into `0..num_groups`; the rounded-up shards still exist (the routing mask needs the power of two) but stay empty, and the docs say so.
- Keys differing only in ASCII case always landed on the same shard. Raw FNV-1a leaves the low bits of the hash dependent only on the low bits of every input byte, and bit 5 is the case bit: "aapl" and "AAPL" collided for every shard count up to 32, deterministically. The hash now ends with a multiply-and-fold finalizer; measured on the ByKey hot path there is no cost. NOTE: existing keys remap to different shards after the upgrade - shard placement was never a persistent contract, but a rolling deploy will see keys move.
- A round robin sender no longer feeds shards whose receiver was dropped. Keeping only some of `into_receivers()` is a legitimate setup, but 1/N of the stream used to bounce off the dead shard with Disconnected forever. Dead shards are skipped on all five send paths; the error surfaces only when every shard is dead. No cost on the healthy path (the skip is the cold branch of the existing disconnect check). `send_timeout` shares ONE deadline across the whole call: each probed shard gets the remaining budget, never a fresh one, so the documented budget holds even when a full shard burns wait time before disconnecting (it used to overrun up to `num_shards * d`).
- Blocking `send()` on a full MPMC channel burned CPU while waiting. Producers waited in a loop of short sleeps, waking 50 thousand times a second each. Now a waiting producer parks on the sender list and is woken by the consumer, with an escalating timeout as a safety net. A wake that lands on the wrong producer is handed on to the next waiter instead of being swallowed, so the tail does not grow with the number of blocked producers. Measured on an idle M2 Max (12 cores): 8 blocked producers went from 0.69 busy cores to 0.05, admission latency after one `pop()` stays at 15 to 65 microseconds median for 1 to 16 parked producers, throughput unchanged. The latency figures scale with core count and machine load; on a busy 2 core box expect several times more, still bounded by the 1 ms safety timeout.

### Changed

- The OS refusing to create a pool thread (thread limits such as RLIMIT_NPROC or a cgroup pids.max, or out of memory) is no longer a panic. At construction it comes back as `PoolError::Spawn` through the same `Result` the constructors already return, with the already started workers wound down cleanly. During lazy scale-up the monitor counts the refusal in the new `spawn_failures` field of the snapshot and retries on the next tick, instead of dying - a dead monitor used to silently take the depth mirror, scaling, rebalance and stall takeover with it. Pool threads are also named now (`hel-pool-worker-N`, `hel-pool-monitor`), so gdb, perf and /proc show which thread is which.
- `Config` builders are `#[must_use]`: `Config` is `Copy` and the builders return a new value, so `cfg.max_consumers(64);` on its own line configured nothing, silently. The batch receive methods are `#[must_use]` too - the returned bool is the disconnect flag, the only exit condition of a drain loop. Fraction fields are validated in the same spirit as the rest of the config: a value outside 0.0..=1.0 or NaN (which froze the monitor - every comparison is false) falls back to its default. Note the behaviour change: `scale_up_fill(2.0)` used as a "never scale up" idiom now silently becomes the 0.80 default - set `max_consumers` equal to `min_consumers` to pin the worker count instead.
- The `Error` impls for send errors no longer demand `T: Debug` (the trait does not need it - our Debug impls are unconditional and skip the payload), so `?` into `Box<dyn Error>`/anyhow works for non-Debug payload types.
- All public handle types (`Sender`, `Receiver`, the shard senders, `ShardReceiver`, the SPSC types, `SyncPool`, `AsyncPool`, `Stop`, futures, streams, iterators) implement a name-only `Debug`, so they can live inside `#[derive(Debug)]` state structs.
- `SpscShard::new(0)` floors to one shard like the MPMC constructors do, instead of panicking - the same config value now behaves the same in every constructor. `SpscSender::shard_id`/`SpscReceiver::shard_id` are read-only methods now, not public mutable fields.
- `ShardReceiver::shard_for` documents loudly that it is meaningful ONLY for `shard_key` channels; on group and round robin channels the number never matched the routing.
- `hel::channel::errors` (the overlapping twin of `hel::channel::error`) is hidden from the docs; it still compiles for compatibility.
- Packaging: the crates.io tarball is now an explicit whitelist, the README file name matches the manifest on case-sensitive filesystems, `rust-version = "1.88"` is declared, and docs.rs builds with all features - the `pool` module used to be missing from the published documentation entirely.
- Channel capacity is now checked at COMPILE time. `CAP` is a const generic, so a value that is not a power of two, or is below 2, fails the build with a clear message instead of panicking on the first run. Before, `round_robin::<u64, 100>(4)` compiled fine and crashed in production. The `mpmc!` and `spsc!` macros already rounded `CAP` up and are not affected. Note: the error surfaces on `cargo build` or `cargo test`, a bare `cargo check` does not reach it.

### Compatibility

- Code that creates a channel with an invalid `CAP` no longer compiles. Such code always panicked at runtime, now the same message arrives at build time.
- `SyncPool::new` and `AsyncPool::new` are no longer public: pools are built via `sync_pool_slot` / `async_pool_slot`, which are unchanged. This ends the churn of internal constructor signatures leaking into the public API.
- Everything else is unchanged.

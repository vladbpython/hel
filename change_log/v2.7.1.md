## [2.7.1]

### Fixed

- Group channels create exactly as many shards as there are declared groups. Before, the count was rounded up to a power of two. With 3 groups the channel had 4 shards, `shards()` said 4, and `into_receivers()` gave a receiver for a shard no data could ever reach. 
Pool built on those receivers also sized itself for the empty shard. Group routing works through a table and never needed the rounding. Measured on the handle send path, no cost.
- `shard_for` on the receiver now uses honest math for any shard count. It only ever mattered for `shard_key` channels, and for them the result is exactly the same as before, bit for bit.
- Hash distribution test runs under Miri too. The sample shrinks from 100 thousand keys to 2 thousand there. The hash is deterministic, so the small sample gives the same numbers on every run and cannot flake.
